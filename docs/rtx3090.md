# Qwen3.8 Flash Next on RTX 3090s

Branch `rtx3090` of leflakk/TensorFold: compute capability 8.6 and tensor parallelism over 1, 2, 4 or 8 GPUs of
one host, for `TensorFold/Qwen3.8-Flash-Next-MLX-4bit-MTP` (also published as `Vontra/...`).

## Which checkpoint

| | MLX 4-bit g32 + MTP (chosen) | EXL3 `4.05bpw_h6_ng6` |
| --- | --- | --- |
| GPU-resident bytes | 75.2 GiB (experts 70.3) | 63 GiB |
| Bytes read per decoded token (1 row) | ~4.2 GB | ~5.3 GB: dense layers at 6 bits, hyper-connections fp16 (1.28 GB) |
| Dequantization | shift + one fma per group: memory-bound | trellis decode: compute-bound on Ampere at 4 bits |
| Prompt speed (TensorFold, GB10) | 2,300-2,500 tok/s | 930-970 tok/s |
| Multi-GPU in TensorFold | yes (this branch: 2, 4, 8) | one GPU only (does not fit a 3090) |
| n-gram table | 32 GB (4-bit) | 39 GB (6-bit) |

EXL3 gives better quality per bit, but on Ampere the MLX checkpoint is the faster one for both prompts and decode.

## n-gram (PLE) tables

They stay on the host. Fastest: in RAM, locked (the default when the host has room: one rank reads them ahead and
`mlock`s them; raise the limit with `ulimit -l unlimited`). `--ple-on-ssd` reads each lookup from disk: a few
percent slower decode, ~32 GB less RAM. Every rank maps the same page cache, so the RAM is counted once.

## Host settings

- `ulimit -l unlimited` for the user that serves (e.g. `/etc/security/limits.d/99-tensorfold-memlock.conf`:
  `youruser - memlock unlimited`), or the n-gram tables cannot be locked and may page from disk.
- RAM: the 32 GB tables are pinned while the weights load (when the host has them plus 8 GiB free), so the
  checkpoint's other pages stay readable by every rank from the page cache.

## Install (no Docker)

```bash
git clone -b rtx3090 https://github.com/leflakk/TensorFold.git && cd TensorFold
python -m venv .venv && . .venv/bin/activate
pip install torch                      # any CUDA build of torch; nvcc of the same CUDA major for the JIT kernels
pip install -e .
hf download TensorFold/Qwen3.8-Flash-Next-MLX-4bit-MTP
```

The CUDA kernels compile on first start (a few minutes, once; cached in `~/.cache/torch_extensions`).

## Before serving: checks, in this order

```bash
python tools/fastcomm_check.py --world 8                       # host-memory collectives: bit-exact + latency
pytest -q tests/cuda/test_flashnext_tp_wide.py                 # 4 and 8 ranks as threads on ONE GPU, small model
pytest -q tests/cuda/test_flashnext_tp.py tests/cuda/test_flashnext_forward.py
```

## Serve

```bash
HF_HUB_OFFLINE=1 tensorfold serve TensorFold/Qwen3.8-Flash-Next-MLX-4bit-MTP --tp 8 --host 0.0.0.0 --port 8080
```

Without `--master`, `--tp N` starts ranks 1..N-1 itself (one process a GPU, CUDA_VISIBLE_DEVICES with the rank's
GPU first). Rank 0 serves HTTP. Check drafted against serial output with `"draft": false` on a request.

`--tp 4` fits too (about 20 GiB of weights a GPU, a short KV window left); `--tp 8` leaves ~12 GiB a GPU for the
caches. `--parallel N` (several requests decoded together) is one-GPU only for now.

## Variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `TF_COMM` | `shm` | `shm`: partial sums through pinned shared host memory (rank-ordered fp32 sums, one kernel, graph-captured); `nccl`: NCCL all-gathers (upstream behavior) |
| `TF_PREFILL_COMM` | `nccl` | prompt-chunk sums (>1 MB): NCCL all-reduce (faster over PCIe); `shm` keeps rank-ordered sums, so a resumed prompt rounds exactly like a fresh one |
| `TF_PREFILL_PARTIALS` | `bf16` | prompt-chunk partials sent as bf16 (half the bytes) or `fp32` |
| `TF_DECODE_PARTIALS` | `bf16` | decode-window partials as bf16 or `fp32` (drafted rows equal serial ones either way) |
| `TF_FASTCOMM_SHOT` | `auto` | `1`/`2` one/two-shot with flags, `3`/`4` the LL forms (same bits); auto: `2` (measured fastest on 8x 3090) |
| `TF_FASTCOMM_GATHER_LL` | `1` | sampling candidates gathered in the LL form (7 us against 12.6 with flags) |
| `TF_PROFILE_DECODE` | unset | `N`: rank 0 prints every N rounds where a decode round's time went (adds a sync per phase) |
| `TF_LOAD_DIRECT` | unset | `1`: read the checkpoint with O_DIRECT on every rank (default for local ranks: shared page cache) |
| `TF_NCCL_LIB` | found | path to libnccl.so.2 when the search (system, torch/lib, pip `nvidia/*/lib`) misses it |
| `TF_FASTCOMM_BLOCK_BYTES` | `2048` | bytes of a rank's share one block moves (smaller: more blocks, more PCIe requests in flight) |
| `TF_FASTCOMM_TIMEOUT` | `600` | seconds a rank waits for another before trapping |
| `TF_ISOLATE_GPUS` | unset | `1`: each rank sees only its own GPU |
| `TENSORFOLD_MEMORY_RESERVE_GIB` | 1.5 on 24 GB cards | what the startup budget leaves free on each GPU |

## Measured (8x RTX 3090, PCIe, no NVLink, EPYC 7532, `567417c`)

| | |
| --- | --- |
| Startup | 357 s (n-gram tables locked after the load: 165 s of it, since pinned during the load) |
| Memory a GPU after load | ranks 0-3 17.5 GB, ranks 4-7 13.8 GB (195,081-token window) |
| Decode, one stream, MTP | 116-169 tok/s (sampled/greedy, chat/code), 184 tok/s on a 300-token code reply |
| MTP acceptance | 75-83 % |
| Cold prefill 2k-64k | 2,380-2,620 tok/s |
| Exactness | drafted and `"draft": false` replies have the same `token_sha` |
